Time Complexity = input size N perigina appudu mana algorithm work entha fast ga periguthundo.

Telugu: Input size N chinnaga unte slow algorithm kuda okay. N pedda ayye koddi, algorithm entha work chestundo important.

Important: Big-O usually focuses on the growth rate, not exact seconds.
Example: O(2N), O(100N), O(N) — growth point of view lo same family: O(N).

3. Complexity → Pattern mapping

O(N!) / O(2ᴺ)

Backtracking = every choice ni try chesi, tarvata undo.

Permutation = elements order arrangements.

Subsets = every element ki take / don't take.

Bitmask = take/not-take decisions ni bits tho represent cheyyadam.

O(N³) / O(N²)

Brute Force = possible pairs/triples ni directly try cheyyadam.

DP = repeated subproblem results ni store chesi reuse cheyyadam.

N small/moderate ayite quadratic/cubic sometimes acceptable.

O(N log N)

Sorting is a common reason.

Sort first → then binary search / two pointers / greedy pattern use cheyyachu.

“Sort chesi problem simple cheyyacha?” ani always ask yourself.

O(N)

Hashing, Two Pointer, Sliding Window, Prefix/Suffix.

Usually array ni one/few passes lo process chestam.

O(log N)

Binary Search main example.

Every step lo search space roughly half avutundi.

O(1)

Direct lookup or fixed amount of work.

Example: array index access a[i] (typical array model).

5. Tiny examples — every concept from zero

Example A — O(N)

Largest number find cheyyali.

max = a[0]
for x in a:
    max = max(max, x)

Array once scan → O(N).

O(N) because N elements ni inspect chestunnam.

Example B — O(N²)

Every pair check cheyyali.

for i = 0..N-1:
    for j = i+1..N-1:
        check(a[i], a[j])

Two dimensions of work → O(N²).

N=1000 ayite roughly million-scale pair checks.

Example C — O(log N)

Sorted array lo target search.

left = 0
right = N-1
while left <= right:
    mid = (left + right) // 2
    ...

Each step search range ni half chestundi → O(log N).

Example D — O(N log N)

Sort + one linear scan.

sort(a)       // O(N log N)
scan(a)       // O(N)
total         // O(N log N)

Dominant term is N log N.

Example E — O(2ᴺ)

Every element: take or don't take.

choose(index):
    choose(index + 1)   // take
    choose(index + 1)   // don't take

2 choices × N levels → O(2ᴺ) leaves (roughly).

Example F — O(N!)

All permutations generate cheyyali.

N elements ki arrangements = N!.

N=10 → 3,628,800 permutations. N increase ayite explosion very fast.

Space Complexity: Time matrame kaadu. Extra memory kuda check cheyyali.
Example: HashMap counts → usually O(N) extra space. Sorting can be in-place or use extra memory depending on implementation.
Interview lo “time = ?, extra space = ?” ani rendu cheppadam habit chesko.

7. Senior-level interview checklist

  1. Read constraints first. N entha? Values range enti? Test cases entha?
  2. Write brute force mentally. First correct solution identify cheyyi.
  3. Calculate its complexity. O(N), O(N²), O(2ᴺ)...
  4. Compare with N. N=10⁵ and O(N²) ante likely problem.
  5. Find repeated work. Same values/counts/sums/ranges repeatedly calculate chestunnava?
  6. Pick a pattern. HashMap / sorting / two pointers / sliding window / prefix-suffix / binary search / DP.
  7. State time + space. Interviewer ki clear ga cheppu.

Quick practice

Q1: N = 20 and problem asks every subset. Which family can be considered?

Answer: O(2ᴺ), often via recursion/backtracking or bitmask.

Q2: N = 10⁵, need duplicate/frequency counts. What natural tool?

Answer: HashMap/Map → typically O(N) expected time.

Q3: N = 10⁵ and array is sorted; need to find a target. What should you consider?

Answer: Binary Search → O(log N) per search.
